A clinical study, from authoring to SDTM, on your laptop.

The Provenance Neural Engine™ Community Edition is a free, open reference deployment of a domain-agnostic data engine on an NGSI-LD broker, demonstrated end to end on clinical research, with a sprinkle of AI. No cloud dependency of any kind: no cloud account, no message queue, no object store to provision.

Fifteen-minute walkthrough Source on GitHub

Requires Docker. Apache-2.0. The AI step runs offline by default; add an Anthropic API key when you want a real model.

zsh
$ curl -fsSL https://raw.githubusercontent.com/scientixai/community-edition/main/install.sh | sh stack up, broker health-checked $ docker compose logs scorpio | grep in-memory Profile in-memory activated. $ open http://localhost:8080/setup.html
Also npx pne-community-edition or a plain git clone.

What happens when you run it

Seven steps, in order, each one a real request against a real service. The walkthrough UI drives them; every step is also plain curl.

  1. Author

    A USDM-style study definition becomes NGSI-LD entities in an upstream NEC Scorpio broker, typed with the open T.O.P. cr-domain vocabulary: Study, Arms, Endpoints, EligibilityCriteria, Visits.

  2. Project

    The study design is projected to CDISC SDTM trial-design domains (TS, TA, TI, TV) as Dataset-JSON. Standards are views, not the stored model.

  3. React

    Every write to the broker fires an NGSI-LD subscription that notifies the pipeline directly over HTTP. That one hop replaces SNS, SQS, and a Lambda.

  4. Transform

    sdtm.oak, the open-source CDISC/pharmaverse engine, maps raw execution data to SDTM: controlled terminology, sequence derivation, the real thing.

  5. Query

    DuckDB runs SQL straight over the files in the lake. Athena semantics, zero infrastructure. You can also just ls the lake.

  6. Sprinkle of AI

    A natural-language clinical statement becomes a broker entity and re-triggers the whole pipeline. One model call, or a deterministic offline stub when there is no API key.

  7. Ask

    What did we know about Participant 204 when Protocol v3.0 was implemented at Site 123? Nine source systems, one graph, every step checked against what was in effect at that minute, every fact cited to its source system and time.

Cloud service, replaced

The architecture (an NGSI-LD broker fronting a CDISC pipeline) is inspired by the AWS Garnet Framework, and built without it. The broker itself never needed the cloud: NEC Scorpio ships an in-memory build that runs every broker service in one JVM. SQS was a packaging choice, not a requirement.

Need parts of the cloud back for a production deployment? The lake is deliberately swappable: Postgres, Athena, Trino, ClickHouse, MinIO all fit behind the same small contract.

One engine, many domains

Clinical research is the first anchored domain, not the boundary. Domains are pluggable vocabularies from The Ontology Project; the broker, context, subscription, projection, and lake architecture stays the same. The applicability runs across the healthcare and life sciences value chain, from healthcare delivery through drug development, commercialization, and claims, and into the territory that CMC naturally crosses: manufacturing, quality, and supply chain. Swap the vocabulary and the projections; keep the engine.

What this edition covers

The Community Edition is a complete local reference stack: an off-the-shelf NGSI-LD broker, an open transform engine, Dataset-JSON and SDTM projections, and one optional model call (or an offline stub). It is built for local practice and learning on a single node.
